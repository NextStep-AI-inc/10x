# Harness message notices with smol summaries — design

2026-09-07

## Context

The transcript gate (`TranscriptMessage.isDisplayable`) default-denies
non-conversation roles and `display: false` customs. That stops raw harness
dumps from flooding the chat, but the drops are silent: if omp adds a message
type tomorrow, nobody notices it vanished. This feature makes the gate
observable — a transcript notice per hidden message, with a one-line summary
generated by the user's fast model.

Real data from this user's sessions (the classes the rule must handle):

| Hidden class | Count | Sizes | Content |
| --- | --- | --- | --- |
| `developer` | 10 | 13.8 KB, 1.3 KB ×3, 530, 396, 321, 225 ×3 | Plan-approval walls, system-reminders, resume instructions |
| `plan-mode-context` (`display: false`) | 3 | 8.9 KB ×3 | Plan-mode context blobs |
| `mid-run-todo-nudge` (`display: false`) | 11 | ~178 B each | Steering nudges |

## Decisions (made with the user)

- **Threshold: everything.** Every gate-dropped message with non-empty text
  gets a notice + summary. The threshold stays user-tunable in settings.
- **Toggle: opt-in.** The 10x-side setting defaults off.
- **Model: OMP's `smol` role** (`modelRoles.smol`, e.g.
  `cursor/composer-2.5-fast`), with a 10x-side override dropdown. Summaries
  are generated only when a model resolves — "only if the user has it set in
  OMP". Notices themselves are controlled by the toggle alone and appear with
  static text when no model is configured.
- Summarization channel: `omp -p --model <model> --no-session --no-tools`
  (verified working; ~11 s cold, async so it never blocks the transcript).

## Design

### Catch rule

`isDisplayable` stays a pure predicate. The two places that drop messages
collect descriptors instead of dropping silently:

- `TranscriptReducer.consume` / `load(messages:)` — a `droppedMessages` array
  the controller drains after each consume.
- `TranscriptHistoryMapper` — `TranscriptHistory` gains a
  `dropped: [HarnessMessageDescriptor]` field; `SessionTimelineLoader` passes
  it through.

```swift
struct HarnessMessageDescriptor: Equatable, Sendable {
    let role: String?        // developer, nil, a future role…
    let customType: String?  // mid-run-todo-nudge, …
    let byteCount: Int
    let text: String         // full extracted text, for the summarizer
}
```

A descriptor is recorded only when the extracted text is non-empty (a
`fileMention`-style message with no text has nothing to summarize), and only
once per unique message: the reducer dedups by content signature
(role + customType + text), so `message_start`/`message_end` pairs — and
repeated identical nudges — record one descriptor.

### Notice

`SessionController` turns each descriptor into a `.notice` transcript item
(existing item kind, existing gray row rendering):

1. Immediate, static: `Hidden developer message (13.8 KB)`.
2. When the summary returns: updated in place to
   `Hidden developer message: <summary>`.
3. No summary (no model, spawn error, empty output, timeout): the static text
   stays. There is no intermediate "summarizing…" state, so the no-model path
   never flashes a placeholder it can't fulfill.

The reducer gains `updateNotice(id:message:)`; notices currently only append.

### Summarizer

`HarnessNoticeSummarizer` — small injected service, one method:

```swift
func summarize(_ descriptor: HarnessMessageDescriptor) async -> String?
```

- Cache: content SHA-256 → summary, persisted as a JSON file under the app's
  application-support directory. Reopening a session re-notices but never
  re-summarizes. (The 11 nudges in the wild are two unique texts → two model
  calls ever.)
- Miss: spawn `omp -p --model <resolved> --no-session --no-tools` via the
  existing `OmpCommandRunner`, prompt = fixed instruction + the descriptor
  text truncated to 8 KB. Summary = last non-empty stdout line (`omp -p`
  prints a `Working...` progress line first).
- No explicit timeout: `omp -p` self-terminates after answering. (Known
  ceiling: a hung child leaves the static notice without a summary; the upgrade
  path is a task-group race with a 60 s cap.)
- The summarizer spawns its own one-shot process; it never touches the
  session's omp child.

### Model resolution

Lazy, on first notice per app run: read `modelRoles.smol` via
`OmpConfigService.list()`. If the 10x settings row has an override, that wins.
No model resolved → notices still appear, with static text only (no
"summarizing…"). This keeps the catch useful for users without a smol role
while honoring "only if set in OMP" for the summaries.

### Settings

New app-side section row, same pattern as Preferred IDE
(`IDEPreferenceStore`-style UserDefaults store, structured controls only):

- **Hidden harness messages** toggle — default off.
- **Notice threshold** — dropdown: Everything / 500 chars / 1 KB / 4 KB.
  Default Everything. Below-threshold drops stay fully silent (current
  behavior).
- **Summary model** — dropdown populated from `get_available_models`,
  default "OMP smol role".

### Out of scope

- `display: true` customs truncated by the 4 KB render cap keep the ellipsis
  only — their content is already visible.
- No notices for `toolResult` routing or content-block skips (thinking,
  toolCall, fallback) — those are normal message anatomy, not hidden messages.

## Error handling

- Summarizer spawn/timeout/empty-output → nil → static notice.
- Config read failure → treated as "no smol role" → static notices.
- Cache write failure → in-memory cache only for the session.

## Testing

- Reducer: dropped descriptors collected for developer/unknown roles and
  `display: false` customs; none for user/assistant/toolResult or empty-text
  messages; threshold filters below-threshold drops.
- History mapper: descriptors flow through `TranscriptHistory.dropped`.
- Summarizer: fake runner returns canned stdout → last line parsed; cache hit
  avoids the runner; failure → nil.
- Controller: notice appears immediately, updates in place on summary,
  static text on failure.
- Settings: toggle/threshold/model persist; feature inactive when toggle off.
